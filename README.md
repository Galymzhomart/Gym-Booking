# Gym Booking System — Week 12

Интегрированная сборка от 19 ноября 2026 года.

Приложение для бронирования индивидуальных тренировок. Стек: Node.js, Express и PostgreSQL. Интерфейс доступен на казахском, русском и английском языках.

## 1. Возможности

- Вход с двухфакторной аутентификацией TOTP.
- Просмотр расписания и фильтр доступных тренировок.
- Создание и отмена бронирований с сохранением истории.
- Проверка срока действия абонемента.
- Запрет повторного бронирования занятого слота и пересечений тренировок участника.
- Кабинет ресепшена с отметками посещения и неявки.
- Поиск ближайшей подходящей тренировки.
- Недельный прогресс по посещённым тренировкам.
- Восстановление пароля через одноразовую ссылку.
- Переключение языка интерфейса.

## 2. Восстановление базы

Сборка и восстановление резервной копии проверены на PostgreSQL 17.

1. Создай в pgAdmin пустую базу `gym_booking_integration`.
2. Нажми по ней правой кнопкой → **Restore**.
3. Выбери формат **Custom or tar** и файл `gym_booking_week12_team.backup`, переданный вместе со сборкой.
4. Выполни восстановление.

Этот бэкап уже содержит интегрированную схему, функции и демонстрационные данные. Повторно запускать начальные миграции и seed-скрипты для него не требуется.

Проверенное содержимое копии:

| Данные | Количество |
|---|---:|
| Занятия | 120 |
| Бронирования | 35 |
| Записи TOTP | 0 |
| Сессии входа | 0 |
| Токены сброса пароля | 0 |

Данные таблиц `public.app_user_totp`, `public.app_sessions` и `public.app_password_resets` исключены из командной копии. Структура этих таблиц сохранена.

На новом сервере перед восстановлением подготовь роль `gym_app`, если она указана в правах резервной копии. Используй собственный пароль и проверь права подключения к восстановленной базе.

Пароль роли PostgreSQL действует на весь сервер: его изменение затронет другие приложения, использующие эту роль.

## 3. Настройка приложения

В папке с `package.json` создай `.env` на основе `.env.example`.

Для Windows CMD:

```bat
copy .env.example .env
notepad .env
```

Укажи параметры своего PostgreSQL:

- `DB_HOST` — адрес сервера.
- `DB_PORT` — порт PostgreSQL, обычно `5432`.
- `DB_NAME` — `gym_booking_integration`.
- `DB_USER` — `gym_app`.
- `DB_PASSWORD` — собственный пароль роли.
- `SESSION_SECRET` — собственная случайная строка.

Для создания секрета:

```bat
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Добавь настройки восстановления пароля:

```dotenv
APP_BASE_URL=http://localhost:3000
RESET_TTL_MINUTES=30
MAIL_MODE=outbox
MAIL_FROM="Gym Booking <no-reply@gym.test>"
```

В режиме `outbox` письма сохраняются локально, без отправки через SMTP.

Файл `.env` не публикуется в репозитории.

## 5. Демо-аккаунты и 2FA

Для проверки основных ролей используются:

| Логин | Роль |
|---|---|
| `ayan` | Участник |
| `reception1` | Ресепшен |

Пароли согласовываются внутри команды. В интегрированной базе пароль участника изменялся при проверке восстановления пароля, поэтому старые пароли из предыдущей сборки могут не подходить.

После восстановления командной копии настрой TOTP локально с помощью `database/migrations/enroll_2fa.sql`. Перед выполнением ознакомься с содержимым скрипта: повторный запуск может заменить существующие ключи.

Добавь полученные ключи в Google Authenticator или другое совместимое приложение, выбрав тип «по времени».

Ключи, QR-коды и действующие коды 2FA не публикуются.

## 6. Восстановление пароля

Для участника `ayan` используется демонстрационный адрес:

```text
ayan@gym.test
```

1. На странице входа выбери восстановление пароля.
2. Введи демонстрационный адрес.
3. Открой локальную папку `outbox`.
4. Найди ссылку в письме `.eml` или файле `latest-reset-link.txt`.
5. Перейди по ссылке и установи новый пароль.
6. Войди с новым паролем и кодом 2FA.

Ссылка одноразовая и имеет ограниченный срок действия. Папка `outbox` не публикуется.

## 7. Проверенные сценарии

В локальной интегрированной сборке вручную проверены:

- Восстановление пароля и вход с новым паролем и 2FA.
- Поиск ближайшего подходящего занятия с пропуском конфликтующего времени.
- Отметка посещения через кабинет ресепшена.
- Изменение недельного прогресса с 2/4 до 3/4.
- Перевод показателя прогресса при переключении языка.
- Отображение названий месяцев на казахском языке.
- Исключение пересекающихся занятий из фильтра доступных тренировок.
- Создание командной резервной копии и её восстановление в отдельную базу.

Полный независимый прогон 20 сценариев выполняет Темирлан. Его результаты фиксируются в `qa/test_results.csv`. Перечисленные ручные проверки не заменяют полный прогон.

## 9. Проверка резервной копии

Командная копия успешно восстановлена в базу `gym_booking_restore_check` на PostgreSQL 17.

Для проверки содержимого выполни:

```sql
SELECT
    current_database() AS database_name,
    (SELECT COUNT(*) FROM public.sessions) AS sessions,
    (SELECT COUNT(*) FROM public.bookings) AS bookings,
    (SELECT COUNT(*) FROM public.app_user_totp) AS totp_rows,
    (SELECT COUNT(*) FROM public.app_sessions) AS login_sessions,
    (SELECT COUNT(*) FROM public.app_password_resets) AS reset_tokens;
```

Полученный при проверке результат: 120 занятий, 35 бронирований и по 0 записей в трёх исключённых таблицах.
